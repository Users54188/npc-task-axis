# 上线手册 · 大学 NPC 任务轴

面向**你本人操作**（我没有你的账号权限）。按顺序做，每步都写了去哪点、填什么、怎么验证。
今天 2026-09-24，提报截止 **2026-10-17**，其中备案是唯一不可控环节，**第 1 步今天必须做完**。

---

## 第 1 步 · 注册与备案（今天，不可并行掉）

1. 微信公众平台 → 注册「小程序」→ 主体选**个人**（身份证 + 人脸核验）。
2. 拿到 **AppID**：设置 → 基本设置 → 账号信息。
3. **立刻提交小程序备案**：小程序后台 → 设置 → 基本设置 → 小程序备案。
   - 备案**按小程序账号（AppID）独立申请**，ai-debate-arena 那份不能挪过来用。
   - 但官方提供「**主体复用资料**」：同一主体下已有小程序通过备案，即可复用主体资料，
     省掉大部分填写与一次人脸核验，实际耗时通常明显低于首次备案。
   - 个人主体备案小程序数量上限 **5 个**（已用 1，还有 4 个额度）。
   - 时限：平台初审 1–2 个工作日，管局审核 1–20 个工作日（以实际为准）。
   - **不能**改用 ai-debate-arena 的现有 AppID 参赛：赛事规定 7/17 前已上线/运营的小程序不属于参赛作品。
4. 填 `project.config.json`：把 `"appid": "touristappid"` 换成真实 AppID。

> 验证：后台能看到「备案进行中」状态和受理编号。**把编号记下来**，万一 10/10 还没通过，提报材料里要附它。

## 第 2 步 · 服务类目

设置 → 基本设置 → 服务范围 → 添加类目：

| | 选什么 | 为什么 |
|---|---|---|
| 主类目 | **教育 > 教育信息展示** | 个人主体在教育下**只有这一个**可选，且无资质要求。本产品展示报考时间/费用/官网/查分日，正是"教育信息展示" |
| 副类目 | **工具 > 备忘录**（或 日历） | 兜住任务轴与打卡的工具属性 |

**明确不要选的**：

- ❌ **工具 > 效率** —— 官方类目表里**不对个人主体开放**（仅境外主体有）。
- ❌ **工具 > 预约/报名** —— 我们只提醒 + 复制官网链接，不代办报名，选它会被要求报名服务资质。
- ❌ 任何 AI 问答 / 深度合成相关类目 —— 个人主体拿不到算法备案在用证明，必被驳回。
- ⚠️ 教育信息展示**不支持**教育视频播放/直播、课程产品销售。本产品没有这两类功能，别在提审描述里写"课程""视频课"字样。

> 类目以你在后台类目选择器里**实际能搜到的**为准；搜不到就是不对个人开放。
> 设多个类目时按最严格标准审核，副类目不要选比主类目更敏感的。

## 第 2.5 步 · 备案服务内容 ≠ 小程序类目

这是两套独立体系，都要填，别抄同一个答案：

- **备案服务内容**：选 **工具 / 信息查询** 方向。官方备案指引对教育类标注"个人备案：**不建议选择**"，而工具类"信息查询"注明"个人备案：可选，符合个人性质"。
- **小程序类目**：按第 2 步选 教育 > 教育信息展示。

## 第 2.6 步 · 微信认证：不用做

后台首页会显示「微信认证 未认证」并给出「去认证」入口，页面上那行说明已经写清：
**未完成微信认证不影响后续版本发布**。个人主体本来也不支持微信认证。
赛事只要求"正式上线并能正常运行"，不要求认证 —— 别把时间花在这。

## 第 3 步 · 开通云开发并填 CLOUD_ENV

1. 后台 → 开通「云开发」，创建环境（名称随意，如 `npc-axis`）。
   - 想拿 10 亿 token：公众平台 → **行业能力 → 小程序成长计划** 报名（二期 2026-07-01~12-31，一账号仅一次，自申请起 6 个月有效）。没有环境可以在报名时免费领 6 个月个人版环境。
2. 复制 **环境 ID**，填进 `miniprogram/utils/config.js`：
   ```js
   CLOUD_ENV: '你的环境ID',
   ```
   > 等第 1 步的 AppID 和第 4 步的模板 ID 都拿到后，可以一条命令一次填完三处并校验自洽：
   > `npm run fill -- --appid=wx… --env=环境ID --tmpl=ID1,ID2 --remind=@remind.json`
   > 它会拦住「客户端申请的模板和服务端要发的模板不是同一个」这类只有到点不发提醒才会发现的错；`REMIND_CONFIG` 写不进云控制台，它会打印出来让你粘。先加 `--dry-run` 可以只看校验不写文件。
3. 建两个集合：`taskNodes`、`checkIns`。权限都设为「**仅创建者可读写**」。

> 验证：微信开发者工具编译后，「我的」页的存储模式应显示**云开发在线**，配置清单里 `云开发环境 ID` 变绿。

## 第 4 步 · 申请订阅消息模板

功能 → 订阅消息 → 我的模板 → 从公共模板库选，建议关键词：**考试提醒 / 报名截止提醒 / 成绩公布提醒**。

- 个人主体 + 工具类目通常只有**一次性订阅**，所以代码里是"每次打卡时顺带申请一条额度"，这是设计如此，不是 bug。
- 记下模板 ID 和每个字段的变量名（形如 `thing1` / `date2`）。

填两处，**两边模板 ID 必须一致**：

```js
// miniprogram/utils/config.js
SUBSCRIBE_TMPL_IDS: ['模板ID1', '模板ID2'],
```

```jsonc
// 云开发控制台 → 云函数 remind → 环境变量 REMIND_CONFIG
{
  "reg":   { "templateId": "模板ID1", "fields": { "thing1": "thing5", "date2": "date9", "thing3": "thing7", "thing4": "thing8" } },
  "admit": { "templateId": "模板ID1", "fields": { "...": "按实际模板" } },
  "exam":  { "templateId": "模板ID2", "fields": { "...": "按实际模板" } },
  "score": { "templateId": "模板ID2", "fields": { "...": "按实际模板" } }
}
```

`fields` 的键是**我代码里的语义名**（thing1=任务名、date2=日期、thing3=节点与倒计时、thing4=紧迫提示），值才是模板里的实际字段名。

## 第 5 步 · 部署云函数

微信开发者工具里右键 `cloudfunctions/` 下**全部 5 个目录** —— `login`、`taskNode`、`checkIn`、`remind`、`recognize` → **上传并部署（云端安装依赖）**。少传一个，前端对应的 `wx.cloud.callFunction` 就报「函数不存在」。

`checkIn` 与 `recognize` 调 `security.msgSecCheck`，`remind` 调 `subscribeMessage.send`。官方《云调用》明确：**每个云函数需声明其会使用到的接口，否则无法调用**，声明位置是该云函数目录下的 `config.json` 的 `permissions.openapi`（三个都已写好）。上传时确认把配置文件一起传上去。若部署后仍报 `-604101`（没有权限），按官方说明**稍等 10 分钟**再试 —— 这是权限生效延迟，不是代码问题，别照着报错去改代码。

`remind` 额外两件事：
1. 详情 → 定时触发器，确认 `dailyRemind` 已启用（`config.json` 已写好每天 09:00）。
2. 环境变量加 `REMIND_CONFIG`（第 4 步的 JSON）。

> 验证：云端测试 `login` 应返回 openid；`remind` 手动传 `{"today":"2026-09-24"}`，返回里 `scanned/due/sent` 应为数字而不是 501。

## 卡住了怎么办

- 备案迟迟不过 → 邮件 weixindeveloper@tencent.com 说明赛区与 10/17 截止冲突，附受理编号。
- 想知道个人主体能不能在运行时调大模型 → 同一邮箱问，这决定 `RECOGNIZE_ENABLED` 能不能打开。
- 随时在「我的」页看**上线配置清单**，代码能判定的项会实时变绿；标"云端核对"的两项只能在控制台确认。
- 填完 `SUBSCRIBE_TMPL_IDS` 后去打卡一次：如果模板 ID 抄错或类目不支持，`requestSubscribeMessage` 只会静默 `fail`、界面上毫无动静，现在失败原文会作为**红底「运行报错」**出现在同一张清单里 —— 这是判断"订阅到底通没通"最快的办法，别凭感觉猜。
