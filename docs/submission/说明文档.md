## 二、功能简介

把大学四年要考的证书与要参加的比赛，做成一条游戏化的 **NPC 任务轴**。

1. **任务时间轴（首页）**：每个任务展开为**报名 / 准考证 / 考试 / 查分**四类节点，按真实日期排序铺在一条竖轴上。临近截止的节点自动红底高亮并显示"剩 N 天"，已过的节点置灰。
2. **倒计时与到点提醒**：每个任务生成醒目倒计时。报名截止前 3/1/0 天提醒去报名（此时通常还没报名），标记「已报名」之后再提醒准考证打印（前 1/0 天）、考试（前 7/3/1 天）与成绩公布（当天），四类都走订阅消息。
3. **知识库自动回填**：新建任务时输入名称（如"计算机二级"），260ms 防抖后命中内置的 10 个证书/赛事知识库，自动填入常规报名窗口、准考时间、考试日、查分区间与三段式备考计划。
4. **阶段任务打卡**：月历视图区分已打卡 / 漏打卡 / 今天，漏打卡可补卡；按备考阶段显示科目、今日重点与完成率（阶段内打卡数 ÷ 阶段天数）。
5. **专注番茄钟**：25/5/15 分钟三档，结束后自动写入打卡记录的专注时长与学习标签；每 4 段进入一次长休。
6. **养成外壳**：经验值、7 级等级、7 章剧情、连续打卡天数、6 枚徽章，以及一只纯本地预设台词的学习桌宠。
7. **数据在线与同步**：两张在线数据表，跨设备同步，离线可用。

## 三、应用场景

- **大二下的密集报考期**：一学期同时面对四级、计算机二级、教资笔试，三者报名窗口各自分散在不同教务系统，靠记忆和室友提醒。
- **报名窗口极短且不可补**：CET 部分院校考位紧张，报名只开放数日；NCRE 由各省自行安排，错过只能等下一轮。
- **备考节奏无外部约束**：距考试还有 80 天时"今天该学什么"没有答案，导致前期松、后期崩。
- **宿舍/班级扩散**：任务轴本身是一张可视化的时间地图，适合截图分享到群里，同专业同学的时间节点高度重合。

## 四、解决的实际问题

| 问题 | 本作品的处理 |
|---|---|
| 漏报名（不可逆损失） | 报名截止前三档提醒 + 首页红色高亮 + 倒计时 |
| 不知道各考试什么时候报名 | 内置知识库回填常规窗口，并显式标注「需按当年官方公告核对」的校验点 |
| 长周期备考无节奏 | 从考试日倒排三段计划，各阶段给出重点与完成率 |
| 提醒工具与学习工具割裂 | 番茄钟结果直接写入打卡记录，驱动经验与徽章 |
| 换设备/重装丢数据 | 云开发双表 + 实时回推，本地优先写入不丢离线编辑 |

## 五、技术开发方案

**架构**：微信小程序原生框架 + 云开发（数据库 / 云函数 / 订阅消息）。

- **数据层** `utils/store.js`：本地优先写入 → 云开发落库 → `watch` 实时回推。合并策略在 `utils/sync.js`：有未推送改动的行远端不得覆盖；其余按 `updatedAt` 后写胜；远端删除受脏保护；未同步成功的行用业务键（任务 `name|examDate`、打卡 `nodeId|date|subject`）与云端回包认亲，避免重复行；`pull` 请求失败时不清空本地。断网操作进 `syncQueue`，网络恢复后幂等重放并回填云端主键。
- **时间计算** `utils/date.js` + `utils/kb.js`：知识库用「第 N 个星期几」这类相对规则描述考期（如 CET 为 6/12 月第三个周六），运行时按参考日期解析成具体日期，并自动处理跨年窗口（报名 12 月起 → 考试次年 4 月）。
- **云函数**：`login` 握手；`taskNode` 服务端二次校验日期单调性并级联删除；`checkIn` 同任务同日同科目原地合并、备注过 `msgSecCheck` 内容安全；`remind` 每日 09:00 定时触发扫描节点并下发订阅消息；`recognize` 从报名表文字抽取结构化字段（默认关闭，见第七节）。
- **番茄钟**：时间戳基准而非 `setInterval` 累加，只记 `anchorAt` 与剩余秒数，回前台用 `Date.now()` 反算一次校正 —— 小程序切后台会挂起 JS 回调，累加式必然计错。
- **测试**：202 个测试用例，其中 10 个为跨设备端到端旅程（两台设备共享同一云端，验证冷启动→接任务→报名→提醒计划→打卡→长图→离线合并→级联删除），5 个为**页面处理函数冒烟**（把 WXML 里绑定的 43 个处理函数在页面真实可达的状态下逐个调用，只求点下去不抛 —— 详情页的查看态与编辑态互斥，故各跑一遍）。含 `wx` / `cloud.database` / `watch` 运行时桩，可直接驱动真实 `Page` 生命周期与事件处理；另有自研 WXML 解析器校验标签闭合、条件链与表达式合法性，并用真实页面数据渲染模板以捕获求值异常；工程结构测试把守页面三件套、`require` 解析、`tabBar` 注册、云函数 openapi 权限声明、文档自述数字与仓库实际的一致性，以及全仓库语法。`npm run preview` 用真实模板与样式生成 HTML 预览供视觉核对。

## 六、创新点

1. **把"考试报名"从待办清单升维成时间地图**。ToDo 工具记录的是"要做的事"，而考证真正的风险是"在某个极短窗口内必须做的事"。本作品以四类节点为原子单位，让"窗口"成为一等公民。
2. **AI 用在能落地且合规的位置**。个人主体不具备深度合成资质，因此本作品不用 AI 生成内容陪聊，而是用 AI 辅助构建**结构化考试知识库**，运行时以检索匹配回填 —— 响应确定、无幻觉、零延迟成本，且完全避开类目限制。
3. **不对称的提醒语义**。已报名的任务不再提醒报名截止，未报名的任务不提醒考试 —— 提醒与用户所处状态绑定，而不是简单按日期广播。
4. **游戏化服务于备考而非留存指标**。经验值只由真实学习行为（打卡、专注时长、完成考试周期）产生，桌宠不做任何 AI 对话，只做本地预设台词的情绪反馈。

## 八、关于 AI 能力的边界说明（主动申报）

本作品当前**运行时不调用任何生成式 AI 能力**，原因不是技术做不到，而是合规判断：

- 个人主体小程序无法取得深度合成类目的算法备案在用证明；
- 官方文档对"个人主体能否在运行时调用云开发大模型接口"存在两种相反表述（成长计划资格条款未设主体门槛，而云开发算法备案在用证明明确仅非个人主体可申请）；
- 因此在向官方（`weixindeveloper@tencent.com`）确认之前，作品把全部确定性能力建立在**检索式知识库**上，`recognize` 云函数默认返回 501 且客户端开关关闭。

若官方答复允许，打开 `config.js` 的 `RECOGNIZE_ENABLED` 与云函数环境变量 `AI_MODEL` 即可启用「从报名表文字识别任务信息」，该路径的代码与校验逻辑（含"严禁编造日期"的提示词约束、日期单调校验、内容安全前置）已完成并通过 10 个测试用例。
